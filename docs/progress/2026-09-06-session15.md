## Bugs Arreglados

### 1. Chat acumula mensajes (CRÍTICO)
**Problema:** Cuando el usuario enviaba un segundo mensaje, el texto de la respuesta de Luna se acumulaba en el mismo bubble de chat en vez de crear uno nuevo. Las variables `streamingDiv` y `streamingContent` no se reseteaban entre mensajes.

**Archivo:** `electron-app/src/index.html`

**Fix aplicado:**
- En `sendMessage()`: se resetea el estado de streaming (`streamingDiv`, `streamingContent`) ANTES de enviar el nuevo mensaje. Si había un bubble de streaming activo, se finaliza (se remueve clase `streaming`, se agrega timestamp).
- Agregado `resetStreamingTimer()`: timeout de seguridad de 30 segundos. Si el backend nunca envía `streaming === false`, el bubble se finaliza automáticamente.
- El timer se reinicia cada vez que llega un chunk de streaming, y se cancela cuando llega el mensaje final.

### 2. Avatar invisible (CRÍTICO)
**Problema:** El avatar Three.js de Luna no se mostraba en la ventana Electron. La causa raíz: Three.js se cargaba desde CDN (`cdnjs.cloudflare.com`). Sin conexión a internet (o con restricciones de red en Electron), `THREE` no se definía → el `try/catch` solo logueaba un warning y el avatar no aparecía.

**Archivo:** `electron-app/src/index.html`, `electron-app/src/three.min.js` (nuevo)

**Fix aplicado:**
- Descargado `three.min.js` (r128, ~603KB) localmente en `src/`
- Cambiado `<script src="https://cdnjs.cloudflare.com/...">` → `<script src="src/three.min.js">`
- Mejorado el manejo de errores del avatar: si Three.js no se carga o el contenedor no existe, se muestra un fallback visual (emoji 🌙 + texto "Avatar no disponible") en vez de un área en blanco.
- Log de éxito: `✅ Avatar Luna inicializado correctamente`
